VSP-CRM Attendance System

Complete technical report · Generated August 19, 2026 · Laravel 12 + Inertia/React

1. Overview

The Attendance module tracks daily employee presence for internal staff. It combines GPS geofencing with optional office public IP verification to ensure employees check in and out from authorized office premises.

Implemented capabilities (Steps 1–7)
  • Super Admin attendance dashboard with live KPI cards and today’s records
  • Office location CRUD (GPS coordinates, radius, network IPs)
  • Employee-to-office assignment (one office per employee)
  • Employee check-in / check-out with GPS + optional network verification
  • Break start / resume with multiple breaks per day
  • Net working hours calculation (gross time minus breaks)
  • Real-time dashboard refresh via Laravel Reverb / Echo
Not yet implemented
  • Attendance correction requests
  • Advanced attendance reports
  • Automatic late status assignment on check-in
  • KPI filter query params on dashboard (links exist but filtering is not wired)

3. Architecture

The module lives under app/Modules/Attendance/ and is registered via AttendanceServiceProvider.

employees ──1:1── att_employee_office_assignments ──N:1── att_office_locations │ └──1:N── att_attendance_entries ──N:1── att_office_locations │ └──1:N── att_attendance_breaks

Module boundary

The Core Employee model has no attendance foreign keys. Assignment is bridged through att_employee_office_assignments and EmployeeOfficeAssignmentService in app/Services/.

AttendanceDashboard also lives in app/Services/ (outside the module folder) so it can read Core employees without circular provider wiring.

9. GPS Geofencing

Uses the Haversine formula (GpsGeofence) with Earth radius 6,371,000 m. Employee coordinates are compared to the assigned office center; check-in/out is allowed when distance ≤ allowed_gps_radius_meters.

Failure message
You must be within the office premises to mark attendance.

Verification order

  1. Employee has assigned office
  2. Office is active
  3. GPS within radius
  4. Network IP matches (if enabled)

Frontend GPS

navigator.geolocation.getCurrentPosition with high accuracy, 15s timeout. Requires HTTPS or localhost. Errors shown for permission denied, unavailable, or timeout.

10. Office Network Verification

Browser limitation
Web browsers cannot read Wi-Fi SSID or BSSID. The system verifies the employee’s public IP address as seen by the server ($request->ip()). When connected to office Wi-Fi, traffic typically exits through the office’s public IP.

Super Admin configures authorized IPs per office (IPv4, IPv6, or CIDR ranges). When network_verification_enabled is true, both GPS and IP must pass for check-in/out.

Failure message
You must be connected to the authorized office network to mark attendance.

Matching uses Symfony IpUtils::checkIp. Break actions do not require network verification.

11. Attendance Workflow

[No entry today] │ check-in (GPS + network OK) ▼ PRESENT (Working) ──start break──► ON_BREAK ──resume──► PRESENT │ │ │ check-out (not on break) │ check-out blocked ▼ ▼ CHECKED_OUT "End your break before checking out."

Multiple breaks

Employees may take unlimited breaks per day. Each break is a row in att_attendance_breaks. Completed break durations accumulate in total_break_seconds.

12. Time Calculations

Net Working Hours = Check-out time − Check-in time − Total break duration

Server (AttendanceTimeCalculator)

gross_seconds       = check_in_at → min(now, check_out_at)
active_break_seconds = now − active_break.started_at  (if on break)
net_seconds          = gross − total_break_seconds − active_break_seconds

On checkout, net_working_seconds and total_working_seconds are persisted (equal at checkout).

Live timers (employee UI)

  • useNetWorkingDuration — ticks every second; pauses during breaks
  • useBreakDuration — current break elapsed time

Display format

formatDuration: e.g. 2h 15m 30s, 45m 12s, 8s

16. Employee Office Assignment

Super Admin assigns one office per employee on create/edit employee screens.

  • Field: office_location_id (nullable)
  • Stored in att_employee_office_assignments
  • Employee list shows assigned office name
  • Only active offices selectable (current inactive office retained on edit)

21. Operational Setup Checklist

  1. Run migrations: php artisan migrate
  2. Create office locations with GPS coordinates and radius
  3. Optionally enable network verification and add office public IP(s)
  4. Assign each employee to an office (Super Admin → Employees)
  5. Start Reverb for live dashboard: configure .env and run Reverb server
  6. Build frontend: npm run build
  7. Employees use /attendance/mark on premises (and office network if enabled)
  8. Super Admin monitors /admin/attendance
