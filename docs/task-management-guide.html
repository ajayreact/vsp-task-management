Task Management — Product User Guide

A practical guide to the Task Management module as it works in VSP CRM today. This document describes only features that exist in the current application code.

Current Implementation Status · Live Module Generated · 2026-08-14 11:08 Standalone HTML · No app changes

1. Introduction

What Task Management is for, and the real work path from client to timesheet.

Task Management helps your agency plan and deliver client work: set up work clients and projects, create tasks, assign or publish them, track time, attach working files, run creative review, complete work, and approve weekly timesheets.

It is built for internal staff (Super Admin, Admin, Team Lead, Manager, Employee).

Complete workflow (implemented)

Employees→ Work Clients→ Projects→ Tasks→ Assign / Open Board→ Accept / Claim→ In Progress→ Time Tracking→ Working Files→ Creative Review→ Approve / Revision→ Completion→ Timesheets→ Workload
Tip Task Management “Clients” are work clients stored as tm_companies. They live at /tasks/clients.

2. User Roles and Access

Based on seeded system roles and abilities in the current codebase.

Seeded roles: super-admin, admin, team-lead, manager, and employee.

A. Super Admin / Administrator

  • Super Admin — passes a global gate check and can do everything.
  • Admin — is granted every ability in the system catalogue.

They can manage employees and departments, create work clients and projects, view all tasks, assign and publish work, manage capacity, view workload, approve timesheets, and decide creative reviews. They also see the Command Center in agency scope.

B. Manager / Team Lead

The seeded manager role includes Task Management abilities such as:

  • Open Task Management; view and manage work clients and projects
  • View all tasks; create/edit/delete tasks (delete only while unstarted)
  • Assign tasks and publish to Open Board
  • Manage capacity; view workload; approve timesheets; review deliverables
  • View employees and departments (but not create/edit them by default)

Managers do not get employees.manage or departments.manage in the default seed.

C. Employee / Team Member

The seeded employee role can:

  • Open Task Management; view work clients and projects
  • Create tasks (tasks.manage)
  • See own assigned work and the Open Board; claim open tasks
  • Accept or decline direct assignments
  • Use the timer, log manual time, upload working files, submit proofs
  • View and submit own timesheets; manage own availability exceptions

Employees cannot assign work to others, manage clients/projects, view the team workload page, approve timesheets, or decide creative reviews (with the default role).

Status meanings

StatusMeaning
DraftCreated but not yet published or assigned
OpenOn the Open Board, waiting to be claimed
AssignedOffered to someone; awaiting acceptance (label: “Awaiting acceptance”)
AcceptedSomeone owns it; work not started yet
In ProgressWork has started
In ReviewCreative proof submitted; waiting for decision
RevisionChanges requested (or reject); needs another submission
ApprovedProof approved; still needs completion
CompletedFinished (closed)

Who can move status?

  • Assign / Publish — users with tasks.assign, while task is unstarted.
  • Claim — staff with Task access and an employee profile, when task is Open.
  • Accept / Decline — only the assigned employee.
  • Manual status transitions — assignee, or someone with tasks.assign (progress policy), and only to allowed next statuses.
  • Submit proof — assignee (In Progress or Revision) → In Review.
  • Review decision — users with reviews.decide while In Review.
  • Start timer from Accepted — automatically moves to In Progress.

10. How to Assign a Task

Two supported methods: Direct Assignment and Open Board.

A. Direct Assignment

  1. Create the task (Draft).
  2. On the task page, choose an Active employee.
  3. Click Assign (needs tasks.assign).
  4. Task becomes Assigned; an assignment offer is Pending.
  5. The employee opens the task and Accepts or Declines.

On accept: status → Accepted; offer → Accepted.

On decline: optional reason; offer → Declined; assignee cleared; mode → Open; status → Open (returns to board).

Reassignment rules

  • Allowed only while the task is unstarted (Draft, Open, or Assigned).
  • Previous pending offers are marked Reassigned.
  • Once work has started (Accepted or later), reassignment is blocked.

B. Open Board

  1. Create the task.
  2. Click Publish (needs tasks.assign).
  3. Task becomes Open, assignee cleared, mode Open.
  4. Employees browse Open Board and click Claim.
  5. Claim skips acceptance — status goes straight to Accepted.

Direct vs Open Board

12. How an Employee Uses a Task

Simple day-to-day path using only implemented steps.

  1. Log in with your staff account.
  2. Open Tasks (defaults to your work) or the Dashboard action items.
  3. Open a task.
  4. If status is Assigned to you — Accept or Decline. Or claim from Open Board.
  5. Start work (status moves to In Progress when you start the timer from Accepted, or via status actions).
  6. Start the timer while you work.
  7. Pause or stop the timer when you break or finish a session.
  8. Add manual time if you forgot to run the timer.
  9. Upload working files (briefs, references, drafts).
  10. When ready, submit a creative deliverable for review (optional path).
  11. If revision is requested, update the work and submit again.
  12. After approval (or if review is not needed), move the task to Completed.

13. Work Timer

Available on the task detail page when time logging is allowed.

ActionWhat happens
StartCreates a running time entry. If task was Accepted → becomes In Progress.
PauseEnds the running entry and stores duration.
StopSame server behaviour as Pause (ends the running entry).
One active timerAn employee may have only one running timer. Starting another is blocked until the first is paused/stopped.
Manual entryEnter start/end, optional note, billable flag (default on).

Who can log time?

  • The assignee, or someone with tasks.view_all (covering).
  • User must have an employee profile.
  • Task must be workable: Accepted, In Progress, In Review, or Revision.
  • Cannot log if that week’s timesheet is Submitted or Approved.

15. Availability

Task Management → Availability.

Weekly capacity

  • Weekly hours (default 40 if none saved)
  • Working days (default Mon–Fri = days 1–5)
  • Effective from date
  • Only users with capacity.manage can save capacity for employees

Day exceptions

  • Available — optional custom hours for that day
  • Leave — 0 hours
  • Half day — half of baseline, or custom hours
  • Holiday — 0 hours

Employees can edit their own exceptions. Users with capacity.manage can edit exceptions for others and switch between employees.

16. Workload

Task Management → Workload. Requires workload.view.

For each Active employee in a Monday–Sunday week:

  • Assigned hours = sum of task estimated hours for tasks assigned to them in: Assigned, Accepted, In Progress, In Review, Revision
  • Available hours = capacity for the week after leave/holiday/half-day exceptions
  • Utilisation % = assigned ÷ available (or 100% if assigned with zero available)

Bands (thresholds)

BandRule
OverallocatedUtilisation > 110%
BenchUtilisation < 50%
On trackEverything else with capacity
UnavailableAvailable = 0 and Assigned = 0
What is not used Workload does not use timer hours, actual logged time, or Open Board tasks without an assignee.

18. Creative Review and Approval

Optional path for creative work that needs sign-off.

Assignee→ Upload Deliverable→ In Review→ Reviewer

Reviewer options

ApproveApprovedApproved
Request changesChanges requestedRevision
RejectRejectedRevision

  • Each decision creates a review round with optional comments.
  • From Revision, the assignee submits again → In Review.
  • After Approve, someone still moves the task from Approved → Completed.
  • Review permission: reviews.decide while task is In Review.

19. Open Board

Path: /tasks/board.

  • Shows tasks that are claimable: status Open and no assignee.
  • Any staff user with Task access and an employee profile can claim (employee must be Active).
  • Optional filters: department, “my department only”.
  • Sorted by priority (urgent → low), then due date.
  • If two people claim at once, database locking allows only one winner; the other sees an already-claimed error.
  • Claim sets ownership and moves status to Accepted immediately.

22. Complete Example: New Task from Start to Finish

Real-world path matching the current implementation.

Request: Client needs a social media video for Independence Day.

  1. Manager selects or creates Work Client (for example ABC Company).
  2. Manager creates Project “Monthly Digital Marketing” (Active or Planning).
  3. Manager creates Task “Create Independence Day social video” with type Video, priority High, estimated hours 6.
  4. Task saves as Draft.
  5. Manager either assigns a designer directly, or publishes to Open Board.
  6. Employee accepts (direct) or claims (board) → Accepted.
  7. Employee starts the timer → In Progress; logs time while editing.
  8. Employee uploads working files (brief PDF, brand assets ZIP).
  9. Employee submits creative proof (video file) → In Review.
  10. Reviewer requests changes with comments → Revision.
  11. Employee revises and submits a new version → In Review again.
  12. Reviewer approves → Approved.
  13. Task is moved to Completed.
  14. Hours already appear on the employee’s weekly timesheet (Draft) for submit/approval later.

25. Quick Start Guide

How do I start using VSP CRM Task Management?

  1. Create departments (Admin).
  2. Create employees and user logins; set roles (Admin).
  3. Set reporting managers and Active status where needed.
  4. Set weekly capacity and working days (Manager/Admin).
  5. Create Work Clients.
  6. Create Projects under each Work Client.
  7. Add project team members (optional labels).
  8. Create tasks with type, priority, estimates, and due dates.
  9. Assign tasks directly or publish them to the Open Board.
  10. Employees accept assignments or claim board tasks.
  11. Track work with the timer and/or manual time.
  12. Upload working files as needed.
  13. Submit creative proofs when review is required.
  14. Approve or request changes; then complete the task.
  15. Employees submit weekly timesheets; managers approve; check workload.
Remember There is no assignment sound or push notification yet. Tell your team to check Dashboard and Tasks regularly.
